# Backend و پنل مدیریت مدرسه — دفتر کلاسی من

این نسخه از بک‌اند، ساختار مدرسه‌ای را اضافه می‌کند: یک مدیر، چند معلم، کد عضویت مدرسه، گزارش تجمیعی از داده‌های همگام‌شده و مشاهده پرونده همگام‌شده هر معلم. ذخیره محلی برنامه همچنان مستقل است و در حالت آفلاین کار می‌کند.

## پیش‌نیازها
- Node.js 20 یا جدیدتر
- PostgreSQL پایدار
- یک سرویس میزبانی با HTTPS و متغیرهای محیطی
- برای استفاده واقعی، فضای ذخیره‌سازی پایدار/شیءگرا برای فایل‌ها

## راه‌اندازی سرور
1. یک پایگاه PostgreSQL ایجاد کنید.
2. از پوشه `backend`، فایل `schema.sql` را روی پایگاه اجرا کنید. این فایل ستون‌های `role` و `school_id` را به جدول‌های نسخه قدیمی نیز اضافه می‌کند.
3. متغیرهای فایل `.env.example` را در داشبورد میزبانی خود تعریف کنید؛ فایل `.env.example` را مستقیماً با رمزهای واقعی commit نکنید.
4. مقدار `JWT_SECRET` باید تصادفی و حداقل ۳۲ نویسه باشد. `ADMIN_SETUP_KEY` را نیز به یک مقدار تصادفی بلند تغییر دهید.
5. در پوشه `backend` اجرا کنید: `npm install` سپس `npm start`.
6. مسیر `GET /api/health` را آزمایش کنید.

## ساخت مدیر و مدرسه
1. فایل `admin-setup.html` را موقتاً در میزبانی وب پروژه قرار دهید یا آن را محلی باز کنید.
2. آدرس API، کلید `ADMIN_SETUP_KEY`، نام مدرسه، نام کاربری مدیر و رمز قوی مدیر را وارد کنید.
3. کد عضویت مدرسه فقط یک بار نمایش داده می‌شود؛ آن را فقط به معلمان همان مدرسه بدهید.
4. پس از ساخت اولین مدیر، endpoint راه‌اندازی مجدد نمی‌تواند مدیر دیگری بسازد. کلید راه‌اندازی را از متغیرهای سرور حذف یا عوض کنید و فایل `admin-setup.html` را از میزبانی عمومی بردارید.
5. در `admin.html` وارد شوید و گزارش مدرسه را مشاهده کنید.

## اتصال برنامه اندروید/وب به سرور
در ابتدای هر دو فایل `index.html` و `app/src/main/assets/index.html` مقدار `window.DAFTAR_CLOUD_ENDPOINT` را به URL عمومی API خود تغییر دهید، برای نمونه `https://api.example.com`؛ هر دو فایل باید یکسان بمانند. سپس هر دو را commit کنید. در workflow، مقایسه این دو فایل کنترل می‌شود.

معلم جدید هنگام ساخت حساب می‌تواند کد مدرسه را وارد کند. حساب آفلاین قبلی نیز می‌تواند در صفحه ورود، نام کاربری و رمز قبلی و کد مدرسه را وارد کند؛ در صورت نبودن حساب ابری، سرور حساب ابری را می‌سازد و snapshot محلی همان دستگاه برای همگام‌سازی آماده می‌شود. اگر حساب ابری قبلاً وجود دارد، از دکمه «اتصال به مدرسه» استفاده شود.

## فایل‌های پنل
- `admin.html`: ورود مدیر و داشبورد وب، آمار معلمان/دانش‌آموزان/کلاس‌ها و خلاصه حضور و غیاب.
- `admin-setup.html`: راه‌اندازی اولیه مدیر؛ پس از استفاده عمومی نماند.
- `schema.sql`: طرح پایگاه داده و مهاجرت امن ستون‌های مدرسه‌ای.

## APIهای اصلی
- `POST /api/admin/setup` — ساخت اولیه مدرسه و مدیر، محافظت‌شده با `X-Admin-Setup-Key`.
- `POST /api/auth/register` — ساخت حساب معلم؛ `schoolCode` اختیاری است.
- `POST /api/auth/login` و `GET /api/auth/me` — ورود و اطلاعات نقش.
- `POST /api/school/join` — اتصال حساب معلم موجود به مدرسه با کد عضویت.
- `GET /api/sync/pull` و `POST /api/sync/push` — همگام‌سازی snapshot اختصاصی معلم.
- `GET /api/admin/overview` — خلاصه مدرسه، فقط برای مدیر همان مدرسه.
- `GET /api/admin/teacher/:id/snapshot` — مشاهده snapshot معلم، فقط برای مدیر همان مدرسه.

## مرزهای امنیت و همگام‌سازی
- مدیر فقط snapshot معلمان عضو مدرسه خودش را می‌بیند؛ هیچ endpoint مدیریتی برای تغییر یا حذف داده معلم اضافه نشده است.
- در شروع همگام‌سازی، snapshot محلی پیش از ادغام پشتیبان‌گیری می‌شود و منطق برنامه از جایگزینی کامل داده محلی با snapshot ابری خودداری می‌کند. داده‌های معلم در snapshotهای مجزا ذخیره می‌شوند؛ این نسخه هنوز پایگاه داده رابطه‌ای مستقل برای هر رکورد دانش‌آموز/حضور و غیاب ندارد. آمار پنل از snapshotهای همگام‌شده استخراج می‌شود.
- آمار پنل آفلاینِ دستگاه‌های معلمان را نشان نمی‌دهد تا وقتی همگام‌سازی موفق شود.
- برای داده‌های واقعی دانش‌آموزان، HTTPS، محدودیت دسترسی میزبان، پشتیبان پایگاه داده و ذخیره‌سازی فایل خصوصی ضروری است. فایل‌های آپلود فعلی در دیسک سرور ذخیره می‌شوند و endpoint دانلود خصوصی هنوز فراهم نشده؛ از آپلود اسناد حساس تا تکمیل ذخیره‌سازی خصوصی خودداری کنید.
- از آنجا که کدهای قدیمی می‌توانند داده‌های محلی داشته باشند، قبل از انتشار عمومی از داخل برنامه پشتیبان خروجی بگیرید و ابتدا با یک حساب آزمایشی مهاجرت را بررسی کنید.
